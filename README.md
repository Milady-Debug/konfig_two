# depviz — этап 2. Сбор данных

Приложение извлекает информацию о прямых зависимостях заданного пакета в
формате Java (Maven) и выводит их на экран. Менеджеры пакетов и сторонние
библиотеки не используются: pom.xml загружается по URL репозитория через
`urllib`, XML разбирается вручную через `xml.etree.ElementTree`
(стандартная библиотека Python).

## Конфигурация (CSV, `ключ,значение`)

| Ключ           | Назначение                                                   |
|----------------|--------------------------------------------------------------|
| `package_name` | Имя пакета: `groupId:artifactId:version`                     |
| `repository`   | URL Maven-репозитория                                        |
| `test_mode`    | Режим тестового репозитория (`true`/`false`) — параметр заложен в конфигурацию, режим реализуется на этапе 3 |

## Структура репозитория

```
src/depviz.py        — исходный код приложения
tests/test_depviz.py — тесты (unittest)
config.csv           — пример конфигурации
run.bat, run.sh      — скрипты запуска
```

## Запуск

```bash
run.bat        # Windows
./run.sh       # Linux/macOS
```

## Тесты

```bash
python -m unittest discover tests
```

## Как это работает

1. По координатам `groupId:artifactId:version` строится URL pom.xml:
   `<repo>/<group/с/точками-заменёнными-на-/>/<artifact>/<version>/<artifact>-<version>.pom`.
2. Файл загружается по HTTP, из него извлекаются прямые зависимости
   (секция `<dependencies>`), поддерживается подстановка `${...}` из
   `<properties>` и наследование `groupId`/`version` от `<parent>`.
3. Все прямые зависимости выводятся на экран. Если версия задана через
   `dependencyManagement` и в pom её нет, выводится `*`.

## Обработка ошибок

- все ошибки конфигурации этапа 1;
- неверный формат имени пакета (не `groupId:artifactId:version`);
- HTTP-ошибки и ошибки соединения при загрузке pom.xml;
- некорректный XML в pom.xml.
