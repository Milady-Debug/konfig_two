# depviz — этап 3. Основные операции

Приложение строит граф зависимостей (с учётом транзитивности) алгоритмом
DFS с рекурсией, корректно обрабатывает циклические зависимости и
поддерживает режим тестирования.

## Конфигурация (CSV, `ключ,значение`)

| Ключ           | Назначение                                                   |
|----------------|--------------------------------------------------------------|
| `package_name` | Корневой пакет: `groupId:artifactId:version` (Maven) или имя из больших латинских букв (тестовый режим) |
| `repository`   | URL Maven-репозитория или путь к файлу тестового репозитория |
| `test_mode`    | Режим тестового репозитория (`true` / `false`)               |

## Структура репозитория

```
src/depviz.py        — исходный код приложения
tests/test_depviz.py — тесты (unittest)
config.csv           — конфигурация для реального Maven-репозитория
config_test.csv      — конфигурация для тестового репозитория
cfg_cycle.csv, cfg_multi.csv, cfg_missing.csv — конфиги демо-случаев
test_repo*.txt       — файлы тестовых репозиториев
run.bat, run.sh      — скрипты запуска
```

## Запуск

```bash
python src/depviz.py --config config_test.csv   # тестовый репозиторий
python src/depviz.py --config cfg_cycle.csv     # демо: циклическая зависимость
python src/depviz.py --config cfg_multi.csv     # демо: больший граф
python src/depviz.py --config cfg_missing.csv   # демо: пакет отсутствует
python src/depviz.py --config config.csv        # реальный Maven-репозиторий
```

## Тесты

```bash
python -m unittest discover tests
```

## Алгоритм

- Граф строится рекурсивным DFS от заданного корневого пакета.
- Каждый узел посещается один раз (состояния `visiting` / `done`), поэтому
  общие транзитивные зависимости не обходятся повторно.
- Циклические зависимости обрабатываются: обратное ребро к узлу,
  находящемуся в текущем пути обхода, фиксируется как цикл, обход по нему
  не продолжается — алгоритм не зацикливается. Найденные циклы выводятся
  на экран.

## Режим тестирования

Вместо URL реального репозитория указывается путь к файлу описания графа
репозитория. Формат файла — строки `ИМЯ: ЗАВ1 ЗАВ2 ...`, пакеты называются
большими латинскими буквами; строки, начинающиеся с `#`, — комментарии.

Продемонстрированные случаи работы с тестовым репозиторием:

1. простой ациклический граф — строится полный транзитивный граф;
2. циклическая зависимость — цикл обнаруживается и выводится
   (`A -> B -> C -> A`), приложение не зацикливается;
3. построение графа от промежуточного узла (C) большого репозитория;
4. пакет, отсутствующий в тестовом репозитории, — предупреждение
   в stderr, узел считается листом.

## Реальный репозиторий

В обычном режиме pom.xml каждого пакета загружается по URL репозитория
(стандартная библиотека Python, без менеджеров пакетов), из pom.xml
вручную извлекаются прямые зависимости, и обход продолжается рекурсивно.
Недоступные или битые пакеты не роняют обход: выводится предупреждение,
узел считается листом.
